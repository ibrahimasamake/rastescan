RasteScan

Photo in, repair ticket out. An AI road inspector that turns a citizen's photo of a damaged road into a classified, scored and located repair job, ranked so the most dangerous spot gets fixed first.

Problem

Complaints arrive. Triage doesn't.

Road damage in a city like Bengaluru gets reported as a photo on WhatsApp, a social post or a call to the ward office. Someone then has to look at each one, decide what it is, how dangerous it is and who should go. An open manhole and a hairline crack sit in the same pile. RasteScan does that first look automatically and consistently, so engineers spend their time on repairs instead of sorting.

Citizen

Takes a photo, the phone adds GPS, sends. Gets a ticket number and sees when it is fixed.

Ward engineer

Sees one queue sorted by danger, with duplicates merged and the damage boxed on every photo.

Field crew

Gets the exact repair method, estimated hours and a map pin. Uploads an after photo to close the job.

How it works

Six steps from photo to fix

1Capture

Phone camera or upload. GPS from the browser or photo EXIF.

2Prepare

Resize to 1024 px, fix rotation, blur faces and number plates.

3Inspect

Vision model runs the inspection prompt and returns strict JSON.

4Verify

Server checks the JSON against the schema and the severity rules.

5Triage

Merge reports within 15 m, rank by urgency, severity and report count.

6Dispatch

Crew gets the job; an after photo is re-inspected to confirm the fix.

Architecture

System design

The AI is one replaceable box. Everything around it is plain, testable code, which is what keeps the demo reliable.

Server checks before anything is saved

        
    
          
  • Strip stray code fences, parse strictly, retry once with a "valid JSON only" reminder.
    • 
          
  • Every enum value must match the schema exactly; otherwise the report goes to manual review.
    • 
          
  • Urgency is recomputed from the severity score bands. If the model disagrees, the server wins and the mismatch is logged.
    • 
          
  • Open manhole is always CRITICAL, whatever the score.
    • 
          
  • Box must satisfy 0 ≤ ymin < ymax ≤ 1000 and 0 ≤ xmin < xmax ≤ 1000. For "None", the box is ignored.
    • 
          
  • Confidence below 0.6 sends the report to a human instead of the queue.
    •

Severity to action

  

    
ScoreUrgencyFix withinTypical caseDefault repair

4.0 – 6.9Medium7 daysPothole under 5 cm, ruttingCold-mix patch and tamper compaction

9.0 – 10.0Critical12–24 hoursOpen manhole, crater over 10 cm, hidden pit under waterBarricade now, then cover replacement or full-depth repair

    
  

  
Queue order: urgency first, then severity score, then number of merged reports, then age. A spot reported by five people rises above an identical spot reported once.

Hosting
AWS on a $50 credit

  
One small server, no managed extras. The jury opens an HTTPS link or the Play test app; both talk to the same backend.

  

    

      
What runs where

      
    
        
  • CloudFront gives a free https://…cloudfront.net address. No domain needed. Browsers only allow camera and GPS on HTTPS.
    • 
        
  • EC2 t4g.small (Ubuntu, ARM) runs FastAPI with uvicorn and serves the built React files. SQLite lives on its 20 GB disk.
    • 
        
  • S3 bucket stores blurred photos. Private; the API hands out short-lived links.
    • 
        
  • Bedrock runs the inspection prompt. The server calls it with its IAM role, so no AWS keys sit in the app or the repo.
    • 
        
  • Security group lets port 80 in only from CloudFront's address list, and SSH only from your IP.
    • 
      

    

    

      
Keep the credit safe

      
    
        
  • Set AWS Budgets alerts at $10, $25 and $40 before launching anything.
    • 
        
  • Do not create a NAT gateway, load balancer, RDS database or SageMaker endpoint. Each one alone can eat most of the credit in a month.
    • 
        
  • Limit uploads to 8 MB and 30 reports per device per hour, so a public link cannot run up the model bill.
    • 
        
  • Stop the instance after the expo; delete it when you are done.
    •

Limits to state up front

    
    
      
  • Depth from one photo is an estimate, which is why the schema uses a depth category instead of centimetres.
    • 
      
  • Boxes from a language model are approximate: good for highlighting, not for measuring.
    • 
      
  • Night, glare and rain lower accuracy; low-confidence results go to a person.
    • 
      
  • The system suggests; an engineer approves. Nothing is closed without a human or an after photo.
    •
